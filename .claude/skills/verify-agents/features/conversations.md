# Conversations

A person talks with one agent in a DM, or with teammates and several agents in a room, where each agent takes a turn after a post. An @mention gives only that agent a turn. An agent that cannot start leaves a notice saying why, in place of the thinking indicator.

## Sub-features

- `dm-open`: open a DM from the sidebar's Agents list, or with Message on the agent's page.
- `dm-send`: send with Enter or Send; the post shows as yours at once.
- `dm-reply`: the agent's reply arrives without a reload, rendered as markdown.
- `dm-keyboard`: reach an agent, write and send using only the keyboard.
- `room-create`: New room with a name, teammates and agents.
- `room-turns`: after a post each agent in the room takes a turn in order, and an agent with nothing to add passes without posting.
- `room-mention`: a post that says @name gives only that agent a turn.
- `room-teammate`: a teammate in the room sees the posts and can post too.
- `stopped`: an agent whose session cannot start leaves a stopped notice with its machine's reason, and stops showing as thinking.
- `interrupt-dm`: Interrupt stops an agent mid-reply.

## How to get to it (user POV)

- Choose an agent in the sidebar's Agents list to open your DM with it.
- Choose Message on an agent's page.
- Choose a conversation in the sidebar's Conversations list.
- Choose New room in the sidebar, name it, tick teammates and agents, and choose Create room.
- In a conversation, write in the Message box and press Enter or choose Send. Write @name to ask one agent.
- While an agent works, choose Interrupt in the conversation's header.

## Driving it with agentsctl

Preconditions:

- An instance from `bin/agentsctl up`, passing `bin/agentsctl doctor`, on the fake Claude harness. Its fixer replies "fake reply" in a DM, and in a room fixer replies and writer passes.

- **Open a DM from the Agents list.** Run `bin/agentsctl browser goto /`, `bin/agentsctl browser click --role button --name fixer --within list:Agents` and `bin/agentsctl browser wait --role heading --name fixer`. The conversation opens with fixer's name as its heading.
- **Send with Enter and get the reply.** Run `bin/agentsctl browser fill --role textbox --name Message --value "Can you look at the checkout total?"`, `bin/agentsctl browser press Enter --role textbox --name Message`, `bin/agentsctl browser wait --role listitem --text "Can you look at the checkout total?" --within list:Messages` and `bin/agentsctl browser wait --role listitem --text "fake reply" --within list:Messages --timeout 30`. Your post shows, then fixer's reply. The record has both, the reply linked to the session that wrote it: `bin/agentsctl db "select m.speaker, m.session_id is not null as linked from messages m join conversations c on c.id = m.conversation_id join agents a on a.id = c.agent_id where c.team_id = {team} and c.kind = 'dm' and a.name = 'fixer' order by m.seq desc limit 1" --wait 30 --expect speaker=agent --expect linked=true`. Capture it with `bin/agentsctl visual shot conversation-dm --ready-role listitem --ready-text "fake reply"`.
- **Check the DM view.** Run `bin/agentsctl browser a11y` and `bin/agentsctl browser console`. No accessibility violation and no console error.
- **The turn made no failed requests.** Run `bin/agentsctl browser network`. Every request the page made since it opened, through fixer's turn and its reply, succeeded.
- **Open the DM from the agent's page.** Run `bin/agentsctl browser click --role button --name "Agent setup"`, `bin/agentsctl browser click --role button --name Message --within region:Agent` and `bin/agentsctl browser wait --role listitem --text "Can you look at the checkout total?" --within list:Messages`. Message on the agent page opens the same DM, not a new one: `bin/agentsctl db "select count(*)::int as n from conversations c join agents a on a.id = c.agent_id where c.team_id = {team} and c.kind = 'dm' and a.name = 'fixer'" --expect n=1`.
- **Send with the keyboard only.** Run `bin/agentsctl browser goto /`, `bin/agentsctl browser tab-to --role button --name fixer --within list:Agents`, `bin/agentsctl browser press Enter`, `bin/agentsctl browser tab-to --role textbox --name Message`, `bin/agentsctl browser type Sent from the keyboard`, `bin/agentsctl browser press Enter` and `bin/agentsctl browser wait --role listitem --text "Sent from the keyboard" --within list:Messages`. Tab reaches the agent and the Message box, and Enter sends.
- **Create a room.** Run `bin/agentsctl browser click --role button --name "New room"`, `bin/agentsctl browser fill --role textbox --name Name --within "form:New room" --value launch`, `bin/agentsctl browser check --role checkbox --name "$(bin/agentsctl db "select login from people where id = {teammate}" --value)"`, `bin/agentsctl browser check --role checkbox --name fixer`, `bin/agentsctl browser check --role checkbox --name writer`, `bin/agentsctl browser click --role button --name "Create room"` and `bin/agentsctl browser wait --role heading --name "# launch"`. The room opens, and lists ben, fixer and writer as members: `bin/agentsctl db "select count(*)::int as n from conversation_members m join conversations c on c.id = m.conversation_id where c.team_id = {team} and c.name = 'launch'" --expect n=4`.
- **Agents take turns, and a pass is not posted.** Run `bin/agentsctl browser fill --role textbox --name Message --value "What should we ship this week?"`, `bin/agentsctl browser press Enter --role textbox --name Message` and `bin/agentsctl browser wait --role strong --text checkout --within list:Messages --timeout 60`. fixer's reply shows, with "checkout" rendered bold. writer took its turn and passed, and its pass is not shown: `bin/agentsctl db "select t.outcome from turns t join agents a on a.id = t.agent_id join conversations c on c.id = t.conversation_id where c.team_id = {team} and c.name = 'launch' and a.name = 'writer' order by t.requested_at desc limit 1" --wait 60 --expect outcome=pass` and `bin/agentsctl browser count --role listitem --text PASS --within list:Messages --expect 0`. Capture it with `bin/agentsctl visual shot conversation-room --ready-role strong --ready-text checkout`.
- **An @mention gives one agent the turn.** Run `bin/agentsctl browser fill --role textbox --name Message --value "@fixer can you take this one?"` and `bin/agentsctl browser press Enter --role textbox --name Message`. fixer answers and writer gets no turn: `bin/agentsctl db "select a.name from turns t join agents a on a.id = t.agent_id join conversations c on c.id = t.conversation_id where c.team_id = {team} and c.name = 'launch' order by t.requested_at desc limit 1" --wait 60 --expect name=fixer` and `bin/agentsctl browser count --role strong --text checkout --within list:Messages --expect 2 --timeout 60`.
- **A teammate sees the room and posts.** As ben, open the room and post. Run `bin/agentsctl browser goto / --as ben`, `bin/agentsctl browser click --role button --name "# launch" --within list:Conversations --as ben`, `bin/agentsctl browser wait --role listitem --text "What should we ship this week?" --within list:Messages --as ben`, `bin/agentsctl browser fill --role textbox --name Message --value "Ben is here" --as ben` and `bin/agentsctl browser press Enter --role textbox --name Message --as ben`. Ada's open room shows ben's post without a reload: `bin/agentsctl browser wait --role listitem --text "Ben is here" --within list:Messages --timeout 30`.
- **Check the room at phone width.** Run `bin/agentsctl browser goto / --viewport phone`, `bin/agentsctl browser click --role button --name Menu --viewport phone`, `bin/agentsctl browser click --role button --name "# launch" --within list:Conversations --viewport phone` and `bin/agentsctl browser overflow --viewport phone`. The room fits a phone without sideways scrolling.
- **A stopped notice says why.** Give writer a plugin whose secret its machine lacks, then message it. Run `bin/agentsctl api POST "/v1/agents/$(bin/agentsctl db "select id from agents where team_id = {team} and name = 'writer'" --value)/plugins" --body "{\"name\":\"notes\",\"kind\":\"stdio\",\"config\":{\"command\":\"npx\",\"args\":[\"-y\",\"notes-mcp\"],\"env\":{\"NOTES_TOKEN\":{\"secret\":\"NOTES_TOKEN\"}}}}"`, `bin/agentsctl browser goto /`, `bin/agentsctl browser click --role button --name writer --within list:Agents`, `bin/agentsctl browser fill --role textbox --name Message --value "Are you there?"`, `bin/agentsctl browser press Enter --role textbox --name Message`, `bin/agentsctl browser wait --role listitem --text "no value for NOTES_TOKEN" --within list:Messages --timeout 30` and `bin/agentsctl browser wait --role listitem --text thinking --within list:Messages --gone`. The notice names the secret and where to set it, and writer no longer shows as thinking. Capture it with `bin/agentsctl visual shot conversation-stopped --ready-role listitem --ready-text "no value for NOTES_TOKEN"`.
- **The notice clears when the agent runs again.** Remove the plugin and message writer again. Run `bin/agentsctl api POST "/v1/agents/$(bin/agentsctl db "select id from agents where team_id = {team} and name = 'writer'" --value)/plugins/notes/delete"`, `bin/agentsctl browser fill --role textbox --name Message --value "Try again."`, `bin/agentsctl browser press Enter --role textbox --name Message`, `bin/agentsctl browser wait --role listitem --text "fake reply" --within list:Messages --timeout 30` and `bin/agentsctl browser wait --role listitem --text "no value for NOTES_TOKEN" --within list:Messages --gone`. writer answers and the notice is gone.
- **A working agent that cannot restart says why.** writer's session is running now. Give it the plugin again, so its next message restarts the session into the missing secret. Run `bin/agentsctl api POST "/v1/agents/$(bin/agentsctl db "select id from agents where team_id = {team} and name = 'writer'" --value)/plugins" --body "{\"name\":\"notes\",\"kind\":\"stdio\",\"config\":{\"command\":\"npx\",\"args\":[\"-y\",\"notes-mcp\"],\"env\":{\"NOTES_TOKEN\":{\"secret\":\"NOTES_TOKEN\"}}}}"`, `bin/agentsctl browser fill --role textbox --name Message --value "And now?"`, `bin/agentsctl browser press Enter --role textbox --name Message` and `bin/agentsctl browser wait --role listitem --text "no value for NOTES_TOKEN" --within list:Messages --timeout 30`. The notice comes back, and the session says it failed: `bin/agentsctl db "select s.status from sessions s join conversations c on c.id = s.conversation_id join agents a on a.id = s.agent_id where c.team_id = {team} and c.kind = 'dm' and a.name = 'writer'" --expect status=failed`.
- **Put writer back.** Run `bin/agentsctl api POST "/v1/agents/$(bin/agentsctl db "select id from agents where team_id = {team} and name = 'writer'" --value)/plugins/notes/delete"`. writer has no plugin that needs a secret.
- **Interrupt a long reply (real Claude).** Ask for something long, then interrupt it. Run `bin/agentsctl browser goto /`, `bin/agentsctl browser click --role button --name fixer --within list:Agents`, `bin/agentsctl browser fill --role textbox --name Message --value "Write a 2000-word story about a lighthouse keeper. Do not use any tools."`, `bin/agentsctl browser press Enter --role textbox --name Message`, `bin/agentsctl browser click --role button --name Interrupt --timeout 120` and `bin/agentsctl browser wait --role button --name Interrupt --gone --timeout 60`. The turn stops within seconds, and its last record says it was aborted: `bin/agentsctl db "select e.body->>'terminal_reason' as reason from events e join sessions s on s.id = e.session_id join conversations c on c.id = s.conversation_id join agents a on a.id = c.agent_id where c.team_id = {team} and c.kind = 'dm' and a.name = 'fixer' and e.kind = 'usage' order by e.seq desc limit 1" --wait 60 --expect reason=aborted_streaming`.

## Gotchas

- The fake harness answers at once, so there is never a moment to interrupt. Interrupt needs a real Claude session.
- A DM shows "Make it a task" under each of your posts, so a list item holding your text also holds that button's name. Match messages by `--text`, never by a whole name.
- An agent's reply is the last text of its turn. A turn that only uses tools posts nothing.
- A room post queues a turn for every agent in the room, one after another, each up to 3 minutes. Wait on the turns in the record, not on a count of messages that are still arriving.
- An agent whose plugin needs a missing secret fails at once and gives up its room turn. The stopped notice stays until that agent's next session in the conversation starts.
- The sidebar is behind the Menu button at phone width.
