# Running the cloud half on AWS

Everything here is ready to run, and nothing has run against AWS yet, since there is no account. The design behind it, with the reasons, is `docs/design/aws.md`. Start with "What you do first" below.

## What moves and what stays

- **Moves to AWS.** The API with its runner and stream server, Postgres, Electric, the forge, and every box with its long-running work.
- **Stays.** Laptops keep the desktop app and their own daemons. This Mac keeps colima and the checks, and stays where the code is written and tested. Until cutover it also keeps running everything, and after cutover its stack is the way back.

## The shape

- **Postgres** on RDS, PostgreSQL 17 on `db.t4g.small`, in private subnets. A parameter group turns on logical replication for Electric. RDS keeps 7 days of automated backups.
- **The server**, a `t4g.large` named `agents-server` on the tailnet. It runs the API, Electric and the forge, through Compose and systemd. `tailscale serve` publishes the people port, as on this Mac.
- **The box host**, an `m7g.xlarge` named `agents-boxes` on the tailnet. Boxes run there as Docker containers. The server reaches its Docker over Tailscale SSH.
- **A backup bucket** in S3 for nightly dumps, kept 35 days.
- **Alarms** by email for the instances, the disks, the API, the backups and the database.
- Both instances run Amazon Linux 2023 on Graviton. Nothing has a public port.

## Security

- **No inbound ports from the internet.** No security group allows anything from an address range. The server's group allows the box host's group to reach the machine port (7700), and the database's group allows the server's group to reach Postgres. The box host's group allows nothing in. The instances have public IPv4 addresses for outbound traffic only, which costs less than a NAT gateway.
- **SSH only through Tailscale.** Port 22 is closed everywhere. Both hosts run Tailscale SSH, and the tailnet policy below says who may connect.
- **Boxes reach the open web, and nothing private.** A box is an agent's computer, so its browser, git, npm, pip and Claude reach any public internet address over any protocol, as boxes on this Mac do. Inside, a box reaches only the server's machine port, which also carries the git proxy. The box host's firewall drops everything a box sends to the box host itself, the VPC, RDS, the metadata endpoint, the tailnet, other boxes and every private range. Boxes look names up at the public resolvers `1.1.1.1` and `8.8.8.8`. The ranges and resolvers are `BOX_CLOSED_RANGES` and `BOX_DNS` in `ops/aws/config.ts`.
- **The metadata endpoint is closed twice.** Both instances require IMDSv2 with a hop limit of 1, so an answer never reaches a container, and the box firewall drops every packet a box sends to a link-local address, 169.254.169.254 among them.
- **Least-privilege roles.** Each instance's role reads only its own SSM parameters and the deployed code bundle, and sends metrics only to the `Agents` namespace. The server's role also reads the database's generated secret, and writes backups under `backups/` only. Neither can delete anything.
- **Where secrets live.**
  - The database password is generated by RDS and kept in Secrets Manager.
  - The Tailscale auth keys, the Claude token for boxes, the forge's config and the webhook secret are SSM SecureString parameters under `/agents/`. You put them there with `ops/aws/secrets.ts`, which reads the value from a file or stdin and never prints it.
  - At every boot the server writes them to `.env`, `forge.json` and `box-claude-token`, each with mode 600.
  - Nothing secret is in user data, the CloudFormation template, logs, the record or a command line.

## Backups and restore

- **What is kept.** RDS keeps automated backups for 7 days, with restore to any second in that window. Every night at 03:30 UTC the server dumps the database and archives the forge, and uploads both to `s3://<bucket>/backups/<time>/`, kept 35 days. A backup older than 30 hours raises an alarm.
- **Not done.** The nightly backup leaves out the boxes' home folders, which hold their workspaces and Claude's session files. They live only on the box host's disk.
- **A backup now.** `sudo systemctl start agents-backup` on the server.
- **Restore a nightly backup** onto the server.

  ```sh
  sudo systemctl stop agents-api agents-compose
  sudo -iu agents node --env-file=agents/.env agents/ops/aws/restore.ts s3://<bucket>/backups/<time>/
  sudo systemctl start agents-compose agents-api
  ```

  It refuses while anything is still connected to the database or using the forge's volume, and names what is. Electric rebuilds its shapes on its own.
- **Restore to a point in time** with RDS. Restore a new instance from the console, with the stack's subnet group, database security group and parameter group. Then change `host` in the database's secret to the new instance and run `sudo systemctl restart agents-secrets agents-compose agents-api` on the server.

## Monitoring

Alarms email the address you deploy with. Confirm the subscription email AWS sends first.

- An instance failing AWS's hardware check is moved to healthy hardware. One failing its own status check is rebooted.
- A disk over 80% full.
- The box host's memory over 85% for 15 minutes. That is the signal to move to the bigger size.
- The API, Electric or the forge not answering for 3 minutes, or the server not reporting at all.
- A backup more than 30 hours old.
- The database with less than 4 GiB free, its CPU over 80% for 15 minutes, or Electric's replication more than 1 GiB behind.

### When the box host should grow

An `m7g.xlarge` has 4 vCPUs and 16 GiB. A box with a desktop and a browser at work takes about 1 vCPU and 2 to 3 GiB, so four at once fit with room for the host. Move to `m7g.2xlarge` (8 vCPUs, 32 GiB) when any of these happens.

- The box host's memory alarm fires.
- More than four boxes with a browser will run at once. Raise `AGENTS_MAX_BOXES` only after the move.
- The box host's CPU stays above 70% through working hours.

To move, deploy with `AGENTS_AWS_BOX_HOST_TYPE=m7g.2xlarge`. The box host stops and starts at the new size in a few minutes, and boxes come back with their home folders.

## What you do first

1. **An AWS account** with billing set up, and a budget with an email alert in Billing and Cost Management, for example at $300 a month.
2. **Sign-in from this Mac.** Turn on IAM Identity Center and give yourself an administrator permission set. Then `brew install awscli`, run `aws configure sso` with a profile named `agents`, and `export AWS_PROFILE=agents`.
3. **A region.** The costs above are for us-east-1. Set it in the profile.
4. **Bootstrap the CDK** once for the account and region: `cd ops/aws && npx cdk bootstrap`.
5. **Tailscale.** Add the policy below in the admin console. Then make two auth keys, pre-approved and not ephemeral, one tagged `tag:agents-server` and one tagged `tag:agents-boxes`, and store each as you copy it.

   ```sh
   pbpaste | node ops/aws/secrets.ts put tailscale-server
   pbpaste | node ops/aws/secrets.ts put tailscale-boxes
   ```

6. **Claude for boxes.** If `~/.agents-app/box-claude-token` does not exist yet, run `claude setup-token` and save the token there with mode 600. Then `node ops/aws/secrets.ts put box-claude-token --file ~/.agents-app/box-claude-token`.
7. **Approve the cost**, about $217 a month to start.
8. **Deploy.** `cd ops/aws && AGENTS_AWS_ALARM_EMAIL=<your email> npx cdk deploy`. Confirm the alarm subscription email, and commit `ops/aws/cdk.context.json`, which now holds the zones and the Amazon Linux image. About 15 minutes later both hosts are on the tailnet, as `agents-aws` and `agents-boxes`, with an empty database.
9. **Pick a cutover window,** and rehearse it once, as below.

Every script has `--dry-run`, which says each step and does nothing. `npx cdk synth` shows the template, and `npx cdk diff` shows what a deploy would change.

## Tailscale policy

Add the tags and SSH rules to the tailnet policy. If the policy already lets every member reach every device, the `acls` entries add nothing and can be left out.

```json
{
  "tagOwners": {
    "tag:agents-server": ["autogroup:admin"],
    "tag:agents-boxes": ["autogroup:admin"]
  },
  "acls": [
    { "action": "accept", "src": ["autogroup:member"], "dst": ["tag:agents-server:80,7700"] },
    { "action": "accept", "src": ["tag:agents-server"], "dst": ["tag:agents-boxes:22"] },
    { "action": "accept", "src": ["autogroup:admin"], "dst": ["tag:agents-server:22", "tag:agents-boxes:22"] }
  ],
  "ssh": [
    { "action": "accept", "src": ["tag:agents-server"], "dst": ["tag:agents-boxes"], "users": ["agents"] },
    { "action": "check", "src": ["autogroup:admin"], "dst": ["tag:agents-server", "tag:agents-boxes"], "users": ["ec2-user", "agents"] }
  ]
}
```

This Mac's Tailscale runs in userspace mode, so reach the hosts through it, for example `tailscale --socket="$HOME/.agents-app/tailscale/tailscaled.sock" ssh ec2-user@agents-aws`.

## The cutover

The data is small. The forge's volume is about 5 MB and all of Postgres about 106 MB, so it moves in a minute or two. Expect about 10 to 15 minutes without the app, most of it checking. Plan an hour.

**Rehearse once, the day before.** Run steps 2 to 5, look around at `http://agents-aws.<tailnet>.ts.net`, then roll back as below. That tries both directions. `test/step11f.ts` already runs steps 3 and 4 on this Mac against a fake AWS, and a task resumes on its box afterwards.

1. **Tell the team.** Let runs finish, or cancel them in the app.
2. **Stop this Mac's server.** The app is down from here.

   ```sh
   launchctl bootout gui/$(id -u)/com.agents.api
   launchctl bootout gui/$(id -u)/com.agents.daemon
   docker stop $(docker ps -q --filter label=agents.instance)
   ```

3. **Export** from this Mac: `node --env-file=.env ops/aws/export.ts`. It dumps the database, the forge and every box's home folder to S3, stores the forge's config, the webhook secret and the Claude token for boxes in SSM, leaves the forge stopped, and prints the next four commands. It refuses while the API or any box is running.
4. **Restore on the server** with the four commands it printed: stop the server's services, write the new secrets, restore, and start again. The restore puts each box's home back on the box host, so the box picks up its workspaces and Claude sessions where it left them.
5. **Build the box image** on the box host, from the server: `sudo -iu agents bash -c 'cd agents && node --env-file=.env server/boxes.ts build'`.
6. **Move the name.** On this Mac, `tailscale --socket="$HOME/.agents-app/tailscale/tailscaled.sock" serve reset`, then `set --hostname=<a new name for this Mac>` the same way. On the server, `sudo tailscale set --hostname=agents-server`. Desktop apps keep the same address and now reach AWS.
7. **Point this Mac's daemon at the server.** In `~/.agents-app/daemon.json`, set `api` to `http://agents-server.<tailnet>.ts.net:7700`. In userspace mode this Mac reaches the tailnet only through its local proxy, so the daemon also needs `HTTP_PROXY=http://127.0.0.1:1055` and `NODE_USE_ENV_PROXY=1` in its launch agent's environment. Then start it again with `launchctl bootstrap`.
8. **Check.** Open the desktop app, message an agent and see it answer, start a run on a box, and see that no alarm has fired.

**Rolling back to this Mac.**

- **If nobody has written anything on AWS yet,** this Mac's data is as it was at step 2. Move the names back (step 6 in reverse, `tailscale serve --bg --http=80 http://127.0.0.1:7710` again on this Mac), run `docker compose start forge`, set `daemon.json` back, and start `com.agents.api` and `com.agents.daemon` with `launchctl bootstrap`.
- **If people have worked on AWS,** first take their work with you. Run `sudo systemctl start agents-backup` on the server. On this Mac, with the API stopped, run `docker compose stop electric forge`, then `node --env-file=.env ops/aws/restore.ts s3://<bucket>/backups/<time>/`, and `docker compose start electric forge`. Then do the steps above. Bringing back what boxes changed in their homes on AWS is not done. The backup leaves box homes out, so those changes stay on the box host.

## Day to day

- **Ship a change.** Commit, deploy with `cd ops/aws && npx cdk deploy`, then on the server `sudo -iu agents node agents/ops/aws/update.ts server`. Boxes pick up a new image when they are recreated.
- **Change what boxes may not reach.** Edit `BOX_CLOSED_RANGES` in `ops/aws/config.ts`, commit and deploy, then on the box host `sudo -iu agents node agents/ops/aws/update.ts boxes`.
- **Change a secret.** `node ops/aws/secrets.ts put <name>` from this Mac, then `sudo systemctl restart agents-secrets agents-api` on the server.
- **Take it all down.** `node ops/aws/down.ts`. It asks you to type the stack's name, and leaves a final database snapshot, the backups and the secrets unless you add `--delete-backups` and `--delete-secrets`. Remove the two machines in Tailscale's admin console afterwards.
