# Running the cloud half on AWS

Nothing here has run against AWS yet, since there is no account. The checks on this Mac stand in for AWS where they can, and `docs/design/aws.md` says what each proves and what none does. The design behind it, with the reasons, is there too. Start with "What you do first" below.

## What moves and what stays

- **Moves to AWS.** The API with its runner and stream server, Postgres, Electric, the forge, and every box with its long-running work.
- **Stays.** Laptops keep the desktop app and their own daemons. This Mac keeps colima and the checks, and stays where the code is written and tested. Until cutover it also keeps running everything, and after cutover its stack is the way back.

## The shape

- **Postgres** on RDS, PostgreSQL 17 on `db.t4g.small`, in private subnets. A parameter group turns on logical replication for Electric. RDS keeps 7 days of automated backups.
- **The server**, a `t4g.large` named `agents-server` on the tailnet. It runs the API, Electric and the forge, through Compose and systemd. `tailscale serve` publishes the API's people socket on port 80, as on this Mac.
- **The box host**, an `m7g.xlarge` named `agents-boxes` on the tailnet. Boxes run there as Docker containers. The server reaches its Docker over Tailscale SSH.
- **A backup bucket** in S3 for nightly dumps, kept 35 days.
- **Alarms** by email for the instances, the disks, the API, the backups and the database.
- Both instances run Amazon Linux 2023 on Graviton. Nothing has a public port.

## Security

- **No inbound ports from the internet.** No security group allows anything from an address range. The server's group allows the box host's group to reach the machine port (7700), and the database's group allows the server's group to reach Postgres. The box host's group allows nothing in. The instances have public IPv4 addresses for outbound traffic only, which costs less than a NAT gateway.
- **SSH only through Tailscale.** Port 22 is closed everywhere. Both hosts run Tailscale SSH, and the tailnet policy below says who may connect.
- **Boxes reach the open web, and nothing private.** A box is an agent's computer, so its browser, git, npm, pip and Claude reach any public internet address over any protocol, as boxes on this Mac do. Inside, a box reaches only the server's machine port, which also carries the git proxy. The box host's firewall drops everything a box sends to the box host itself, the VPC, RDS, the metadata endpoint, the tailnet, other boxes and every private range. Between boxes it was tried only with the packets routed through a stand-in host, not across Docker's own bridge. Boxes look names up at the public resolvers `1.1.1.1` and `8.8.8.8`. The ranges and resolvers are `BOX_CLOSED_RANGES` and `BOX_DNS` in `ops/aws/config.ts`.
- **The metadata endpoint is closed twice.** Both instances require IMDSv2 with a hop limit of 1, so an answer never reaches a container, and the box firewall drops every packet a box sends to a link-local address, 169.254.169.254 among them.
- **Least-privilege roles.** Each instance's role reads only its own SSM parameters and the deployed code bundle, and sends metrics only to the `Agents` namespace. The server's role also reads the database's generated secret, and writes backups under `backups/` only. Neither can delete anything.
- **Where secrets live.**
  - The database password is generated by RDS and kept in Secrets Manager.
  - The Tailscale auth keys, the Claude token for boxes, the forge's config and the webhook secret are SSM SecureString parameters under `/agents/`. The auth keys are single-use and expire within a day, so a key read after first boot joins nothing. A machine replaced later needs a new key there first. You put them there with `ops/aws/secrets.ts`, which reads the value from a file or stdin and never prints it.
  - At every boot the server writes them to `.env`, `forge.json` and `box-claude-token`, each with mode 600.
  - Nothing secret is in user data, the CloudFormation template, logs, the record or a command line.

## Backups and restore

- **What is kept.** RDS keeps automated backups for 7 days, with restore to any second in that window. Every night at 03:30 UTC the server dumps the database and archives the forge, and uploads both to `s3://<bucket>/backups/<time>/`, kept 35 days. A backup older than 30 hours raises an alarm. Backups, restores and the cutover stage their archives in `/var/tmp`, on disk, after checking it has room, and upload them in 64 MiB parts, each with a CRC32 that S3 checks, so an archive can pass S3's 5 GiB limit for one upload.
- **Not done.** The nightly backup leaves out the boxes' home folders, which hold their workspaces and Claude's session files. They live only on the box host's disk.
- **A backup now.** `sudo systemctl start agents-backup` on the server.
- **Restore a nightly backup** onto the server. The backup timer stops too, so no backup runs during a restore.

  ```sh
  sudo systemctl stop agents-api agents-compose agents-backup.timer
  sudo -iu agents node --env-file=agents/.env agents/ops/aws/restore.ts s3://<bucket>/backups/<time>/
  sudo systemctl start agents-compose agents-api agents-backup.timer
  ```

  The server's database holds teams, whose work may be newer than the backup, so the restore refuses at first and prints when the backup was taken. When that is the backup you mean, run it again with `--replace agents` added. It also refuses while anything is connected to the database, uses the forge's or Electric's volume, or runs as a box, and names what is, and when `/var/tmp` has no room for the backup. It changes nothing until those checks pass. Electric rebuilds its shapes on its own. The restored boxes' stopped containers are removed, since their tokens are not the ones the restored database knows, and the runner starts each box again with a new token.
- **Restore to a point in time** with RDS. Stop the API, Compose and the backup timer as above. Restore a new instance from the console, with the stack's subnet group, database security group and parameter group. Empty Electric's volume, since its shapes follow the old database: `sudo docker run --rm -v agents_electricdata:/data alpine:3.20 find /data -mindepth 1 -delete`. Then change `host` in the database's secret to the new instance, run `sudo systemctl restart agents-secrets`, and start the three again.

## Monitoring

Alarms email the address you deploy with. Confirm the subscription email AWS sends first.

- An instance failing AWS's hardware check is moved to healthy hardware. One failing its own status check is rebooted.
- A disk over 80% full.
- The box host's memory over 85% for 15 minutes. That is the signal to move to the bigger size.
- The API, Electric or the forge not answering for 3 minutes, or the server not reporting at all.
- A backup more than 30 hours old.
- The database with less than 4 GiB free, its CPU over 80% for 15 minutes, or Electric's replication more than 1 GiB behind.

### When the box host should grow

An `m7g.xlarge` has 4 vCPUs and 16 GiB. A box with a desktop and a browser at work takes about 1 vCPU and 2 to 3 GiB, so four at once fit with room for the host. Move to `m7g.2xlarge` (8 vCPUs, 32 GiB) when any of these happens.

- The box host's memory alarm fires.
- More than four boxes with a browser will run at once. Raise `AGENTS_MAX_BOXES` only after the move.
- The box host's CPU stays above 70% through working hours.

To move, deploy with `AGENTS_AWS_BOX_HOST_TYPE=m7g.2xlarge`. The box host stops and starts at the new size in a few minutes, and boxes come back with their home folders.

## What you do first

1. **An AWS account** with billing set up, and a budget with an email alert in Billing and Cost Management, for example at $300 a month.
2. **Sign-in from this Mac.** Turn on IAM Identity Center and give yourself an administrator permission set. Then `brew install awscli`, run `aws configure sso` with a profile named `agents`, and `export AWS_PROFILE=agents`.
3. **A region.** The costs above are for us-east-1. Set it in the profile.
4. **Bootstrap the CDK** once for the account and region: `cd ops/aws && npx cdk bootstrap`.
5. **Tailscale.** Add the policy below in the admin console. Then make two auth keys, single-use, pre-approved, not ephemeral and expiring after one day, one tagged `tag:agents-server` and one tagged `tag:agents-boxes`, and store each as you copy it. Each machine's first boot spends its key, and a machine replaced later needs a new one stored first.

   ```sh
   pbpaste | node ops/aws/secrets.ts put tailscale-server
   pbpaste | node ops/aws/secrets.ts put tailscale-boxes
   ```

6. **Claude for boxes.** If `~/.agents-app/box-claude-token` does not exist yet, run `claude setup-token` and save the token there with mode 600. Then `node ops/aws/secrets.ts put box-claude-token --file ~/.agents-app/box-claude-token`.
7. **The cost.** Tayler approved it on 2026-10-14, about $217 a month once it runs, with the `ops/` files. Nothing is deployed until the Mac version settles.
8. **Deploy.** `cd ops/aws && AGENTS_AWS_ALARM_EMAIL=<your email> npx cdk deploy`. Confirm the alarm subscription email, and commit `ops/aws/cdk.context.json`, which now holds the zones and the Amazon Linux image. About 15 minutes later both hosts are on the tailnet, as `agents-aws` and `agents-boxes`, with an empty database.
9. **Pick a cutover window,** and rehearse it once, as below.

Every script has `--dry-run`, which says each step and does nothing. `npx cdk synth` shows the template, and `npx cdk diff` shows what a deploy would change.

## Tailscale policy

One policy for the Mac and AWS. It keeps the grant and the tests that `docs/design/people-port.md` adds for the people socket, puts the AWS server's tag in that grant, and adds what the box host needs: Tailscale SSH from the server, for its Docker, and from admins. Merge it into the policy the tailnet holds now. That policy already has the Mac's grant and the tests, and the rule that let everyone reach everything is gone, so nothing needs removing first. `docs/decisions.md` records this under "Only tailscale serve can name a person". The AWS server's tag in the grant and the box host's SSH rules have not been applied or tried. Tailscale checks the policy when you save it, and runs the tests on every later change.

```json
{
  "tagOwners": {
    "tag:agents-server": ["autogroup:admin"],
    "tag:agents-boxes": ["autogroup:admin"]
  },
  "hosts": {
    "agents-server": "<this Mac's Tailscale IPv4 address>",
    "agents-server-v6": "<this Mac's Tailscale IPv6 address>"
  },
  "grants": [
    { "src": ["autogroup:member"], "dst": ["agents-server", "agents-server-v6", "tag:agents-server"], "ip": ["tcp:80", "tcp:7700"] },
    { "src": ["tag:agents-server"], "dst": ["tag:agents-boxes"], "ip": ["tcp:22"] },
    { "src": ["autogroup:admin"], "dst": ["tag:agents-server", "tag:agents-boxes"], "ip": ["tcp:22"] }
  ],
  "ssh": [
    { "action": "accept", "src": ["tag:agents-server"], "dst": ["tag:agents-boxes"], "users": ["agents"] },
    { "action": "check", "src": ["autogroup:admin"], "dst": ["tag:agents-server", "tag:agents-boxes"], "users": ["ec2-user", "agents"] }
  ],
  "tests": [
    {
      "src": "<a member's login>",
      "proto": "tcp",
      "accept": ["agents-server:80", "agents-server:7700"],
      "deny": ["agents-server:7710", "agents-server:1055", "agents-server:4437", "agents-server:5432",
               "agents-server:5433", "agents-server:3000", "agents-server:3001", "agents-server:3002",
               "agents-server-v6:7710", "agents-server-v6:1055", "agents-server-v6:4437", "agents-server-v6:5432",
               "agents-server-v6:5433", "agents-server-v6:3000", "agents-server-v6:3001", "agents-server-v6:3002"]
    }
  ]
}
```

The `hosts` addresses stay this Mac's after the cutover, so members can still reach it on 80 and 7700 for a rollback. After the cutover the AWS server answers as `agents-server` by name, through its tag. The tests name the Mac by address, so they keep guarding the Mac. If the editor accepts tags in `tests`, add `"tag:agents-server:80"` and `"tag:agents-server:7700"` to `accept` and `"tag:agents-server:3000"`, `"tag:agents-server:3001"` and `"tag:agents-boxes:22"` to `deny`. That was not tried.

This Mac's Tailscale runs in userspace mode, so reach the hosts through it, for example `tailscale --socket="$HOME/.agents-app/tailscale/tailscaled.sock" ssh ec2-user@agents-aws`.

## Day to day

- **Ship a change.** Commit, deploy with `cd ops/aws && npx cdk deploy`, then on the server `sudo -iu agents node agents/ops/aws/update.ts server`. Boxes pick up a new image when they are recreated.
- **Change what boxes may not reach.** Edit `BOX_CLOSED_RANGES` in `ops/aws/config.ts`, commit and deploy, then on the box host `sudo -iu agents node agents/ops/aws/update.ts boxes`.
- **Change a secret.** `node ops/aws/secrets.ts put <name>` from this Mac, then `sudo systemctl restart agents-secrets agents-api` on the server.
- **Change a setting.** Settings that are not secrets, such as `AGENTS_MAX_BOXES`, go in `/home/agents/.agents-app/settings.env` on the server, which `fetch-secrets.ts` never writes. The API reads it after `.env`, so a setting in both takes its value from `settings.env`. Then `sudo systemctl restart agents-api`.
- **Run an admin command.** On the server, `sudo -iu agents bash -c 'cd agents && node --env-file=.env server/admin.ts <command>'`.
- **Take it all down.** `node ops/aws/down.ts`. It asks you to type the stack's name, and leaves a final database snapshot, the backups and the secrets unless you add `--delete-backups` and `--delete-secrets`. Remove the two machines in Tailscale's admin console afterwards.

## When Tailscale is down

SSH reaches the hosts only through Tailscale, so with Tailscale down, or a host that never joined, there is no way in until you open one. The instances run Amazon Linux 2023, which ships the SSM agent, but their roles lack the policy Session Manager needs.

1. In the IAM console, attach the managed policy `AmazonSSMManagedInstanceCore` to the instance's role, which the stack names after `ServerRole` or `BoxesRole`.
2. From this Mac, `aws ssm start-session --target <instance id>`, with the Session Manager plugin for the AWS CLI installed. The instance id is in the EC2 console.
3. When done, detach the policy again.

## Boxes on this Mac

Boxes on this Mac reach the internet, as boxes on AWS will. `ops/box-firewall.sh` runs in colima's VM and does two things.

- It keeps every container off this Mac except on the machine ports, 7700 and 7701.
- Tayler approved on 2026-10-14 that boxes here also reach nothing private, as on the box host. For packets from Docker's default bridge, `docker0`, where boxes run, it drops each range in `BOX_CLOSED_RANGES` and everything sent to the VM itself except DNS on port 53, where the VM's resolver answers.

Answers to connections made from outside a box still pass, so published ports keep working. Compose's services run on their own network and are not sent through the new chains. They reach what they reached, and this Mac only on its machine ports, as before. Any other container on the default bridge loses the private ranges too, checks' helper containers included.

This takes something away. Boxes here reach the VM's own services and private addresses today, and will not. Boxes also run without `NET_RAW` now, which `docs/design/aws.md` explains.

**What was tried.** `test/step11g.ts` runs the script in a copy of the VM's network made of containers, with 33 checks. The live VM was left alone, so the rest ran by hand on 2026-10-14 in a throwaway colima profile with its own VM, of the same type, runtime and network mode as the live one, and deleted afterwards. `docs/design/aws.md` lists what it showed. The live VM's rules and its `colima.yaml`, Docker's config and the SSH config were compared before and after, and none changed.

**Not done.**

- Nothing was applied to the live VM. The steps below are for Tayler.
- Two boxes on `docker0` still reach each other. The bridge passes their packets between them without calling iptables, so no rule in this script sees them. Step 3 below turns `icc` off, which closes that. It was tried in the copy and not in the live VM.
- A rerun empties each chain before it refills it, so packets from boxes pass unfiltered for a moment. The box host's firewall replaces its chain in one transaction.
- IPv6 is not filtered. A container on the default bridge had only `::1` and reached no IPv6 address.
